TombEngine Renderer

Reference of the renderer on develop_new_renderer: how a frame is prepared and drawn, how level data reaches the GPU, every pass and shader feature, the four graphics API backends, configuration, debugging, benchmarking, known issues and planned work. Paths are relative to TombEngine/ unless stated otherwise.

1. Overview

The renderer has three layers. The frontend decides what is drawn, on the CPU only. The backend owns every GPU resource and records the passes. The RHI is a small rendering hardware interface with one implementation per graphics API.

LayerClassFoldersRole
FrontendRenderer (g_Renderer)Renderer/, Scene/, UI/, Sky/, Structures/API used by the game code. Portal culling, item, static, light and effect collection, sprites, sorted transparent faces, sky state, the 2D layer.
BackendSceneRenderer (Backend::g_SceneRenderer)Renderer/Backend/Uploads the level at load, builds the per-frame GPU data, records the frame passes, composes the 2D layer and submits.
RHIRHI::IDevice and friendsRenderer/RHI/Interfaces modeled on SDL GPU, implemented for Vulkan and Direct3D 12 (through SDL GPU), DirectX 11 and OpenGL 4.5.

Design rules

  • One renderer, four APIs. Vulkan is the default and the main optimization target; DirectX 11, Direct3D 12 and OpenGL 4.5 run the same backend code through the same RHI.
  • Persistent GPU data. Level geometry and textures are uploaded once. Per frame only instances, lights, light clusters, bones, materials (when changed), sprites, decals, sorted indices, debris and debug vertices are uploaded, all through one upload ring in one copy pass.
  • Instanced, state sorted draws. Objects are drawn by instance index; identical rigid meshes share instanced draws; opaque, additive and distortion draws are sorted by alpha test, texture array group, layer and material.
  • Offline shaders. Shaders are compiled at build time into four binary formats. The pipelines a level can bind are created at load; anything missed is created on first use.
  • No branches for missing maps. Room and object pixel shaders exist in variants without the normal, ORSH and emissive reads and without alpha test, chosen per draw.
  • Everything named. Every pass is a debug group and every resource and pipeline has a readable name for RenderDoc, Nsight and Radeon GPU Profiler.
  • Classic look by default. Ambient occlusion, TAA, HDR, glow, reflections, shadows and the volumetric sky are additive; with them off the image matches the classic renderer (verified against reference images of the retired legacy renderer).

3. Threads and frame lifecycle

The game logic, the frontend and the backend recording run on the game thread. The main thread owns the window and the event loop (window thread). Per frame:

  1. DrawPhase (Game/control/control.cpp) calls Render(f), RenderTitle(f) or RenderFreezeMode(f, full), then Lock() and ApplyPendingWindowResize(). GamePhase starts with PrepareScene() and SaveOldState().
  2. Render interpolates the camera and runs RenderScene (4.2), which ends with SubmitFrame: it fills a Backend::FrameEnvironment and calls g_SceneRenderer.RenderFrame(view, environment).
  3. RenderFrame waits for the oldest frame in flight (FRAMES_IN_FLIGHT_MAX = 2 fences), collects and uploads the frame data and records the fourteen frame passes.
  4. The frontend builds the ImGui draw data (debug mode), then PresentFrame fills the UiFrame and calls SceneRenderer::FinishFrame(ui), which draws the 2D layer over the scene into Frame.Final and submits.
  5. Presentation: DirectX 11 and OpenGL present on the game thread. SDL GPU must acquire the swapchain on the window thread, so PresentOnWindowThread blits Frame.Final to the swapchain there, with three swapchain frames in flight.
  6. With high framerate on, frames interpolate between the 30 Hz game ticks. With SDL GPU and vertical sync, PaceFrame sleeps until the next refresh interval, since mailbox presentation does not block.

OpenGL keeps its context current on one thread: a thread that stops rendering calls SceneRenderer::ReleaseThread() (before the game thread starts, at game thread start and exit, and around the asynchronous level load). A new rendering thread needs the same hand-off.

4.2 RenderScene

RenderScene(view, mode) runs these steps in order:

  1. ResetDebugVariables.
  2. CollectMirrors, CollectRooms: rooms visible through portals and everything they contain (4.3, 4.4).
  3. UpdateLaraAnimations, UpdateItemAnimations, CollectLightsForCamera (picks the shadow light), RenderBlobShadows, PrepareSceneSprites.
  4. PrepareSkyEffects: sky draw records and uniform blocks (section 9).
  5. CollectSortedFaces, SortTransparentFaces (section 5).
  6. CollectHud: 3D HUD, pickups, 2D HUD, overlays, display sprites and strings into the UiFrame.
  7. CollectFrameStats, then SubmitFrame, which calls the backend.
  8. ClearScene and CalculateFrameRate.

RenderView (Scene/RenderView.h) holds the camera (view, projection, frustum, position, direction, near plane 32, far plane from the level, at least 3200 or else 102400) and the lists RoomsToDraw (portal traversal order), LightsToDraw (dynamic lights of the view), FogBulbsToDraw, SpritesToDraw, DisplaySpritesToDraw, SortedStaticsToDraw (by static object number), TransparentObjectsToDraw, TransparentPolygonsToDraw, TransparentSortKeys, LensFlaresToDraw and Mirrors.

4.3 Portal culling

CollectRooms resets the rooms and doors, then calls GetVisibleRooms from the camera room with the full screen rectangle (-1, -1, 1, 1):

  • On the first visit of a room it is pushed to RoomsToDraw and its lights, decals, items and statics are collected. Every visit grows the room rectangle (RendererRoom::ViewPort) to the union with the incoming rectangle.
  • For each door, the dot product of its normal with the direction to the camera is computed once per frame; a door facing away is skipped for the rest of the frame.
  • CheckPortal projects the four portal corners once per frame. Corners behind the camera extend the rectangle to the screen borders their edges point to; four corners behind reject the portal. The rectangle is intersected with the parent rectangle and the recursion continues with it.
  • Guards: a room among the last five of the visit stack is skipped (cycle guard), and recursion stops past a depth of 64 (MAX_SEARCH_DEPTH) for rooms already visited.
  • If the player room was not reached but neighbors the camera room, it is added with the full rectangle.

The backend uses the rectangle as the scissor of the room draws and tests each room chunk against it (6.7). Mirrors are collected first (CollectMirrors): enabled mirrors whose room is the camera room or the player room; items and statics of a reflected room skip frustum culling.

4.4 Items, statics, effects and lights

  • Items (CollectItems): skipped when invisible, fully transparent, hidden or without a renderer object. The frustum test uses the mesh spheres (radius x 1.5) and runs only when the shadow mode is None and the room is not reflected, so off-screen casters and reflected items are still collected. The world matrix includes the root motion correction of the animation. Interpolation resets when the item teleports more than one sector.
  • Effects (CollectEffect): one mesh, room ambient light, no frustum test.
  • Statics (CollectStatics): refreshed only when dirty; sphere frustum test; lights collected once and cached until the static moves; grouped by object number for instancing.
  • Lights (CollectLights): room lights of the room and its neighbors within 20 sectors and within their outer radius, plus dynamic lights where requested. More than MAX_LIGHTS_PER_ITEM (8) candidates are sorted by local intensity. Items, effects and statics collect room lights only; dynamic lights reach them through the light clusters (7.2). CollectLightsForCamera (radius 4 sectors) picks the brightest shadow casting point or spot light as the shadow light.
  • View dynamic lights (CollectLightsForRoom): dynamic lights whose sphere touches a visible room, at most 48 per view (NUM_LIGHTS_PER_BUFFER).
  • Light fades: after a room change the ambient light and the light set blend from the previous room over ten steps of 0.1.
  • Dynamic lights (AddDynamicPointLight, AddDynamicSpotLight, AddDynamicFogBulb) are double buffered per game tick so moving lights interpolate (matched by hash); with ReflectLights, lights inside a mirror room get a reflected copy.
  • Decals (CollectDecalsForRoom): decals in the frustum whose room or a neighbor is the room.

4.5 Fog bulbs, lens flares and blob shadows

  • Fog bulbs: fog bulb lights of all active rooms plus dynamic fog bulbs, tested against the frustum with radius x 1.2, sorted by distance, at most 32.
  • Lens flares: flares in front of the camera, the global (sun) flare first, at most 8. The global flare color is scaled by the cloud transmittance read back from the GPU and by a fade below the horizon, and is hidden under the underwater sky.
  • Blob shadows (RenderBlobShadows): spheres for visible items with a shadow type; the player gets four (hips, torso, feet). More than ShadowBlobsMax (default 16) are sorted by distance to the player; the backend takes at most 16.

4.6 High framerate interpolation

Game logic runs at 30 Hz. SaveOldState stores the previous state of items, effects and statics each tick; the renderer interpolates with _interpolationFactor: the camera (position, direction, view, projection, FOV), item world matrices and the 32 bone matrices, statics, particles, ropes, swarms, hair, laser beams, streamers, strings and display items. The frame rate is the smoothed present rate clamped to 30..refresh; without high framerate it is 30.

4.7 Animation and the player

  • UpdateAnimation walks the bone tree (up to 32 bones) with frame blending (position lerp, quaternion slerp), extra rotations and mutators. UpdateItemAnimations adds vehicle and creature joint rotations.
  • Skinning modes (RendererEnums.h): Static 0, None 1, Full 2 (level setting Graphics.Skinning with a skin mesh), Classic 3 (the player joints).
  • UpdateLaraAnimations composes the body, the arms per weapon (pistols, revolver, back weapons, flare and torch) and torso and head rotations. The player is drawn as rigid meshes plus joint meshes (classic) or a full skin; holsters; hair units as skinned or rigid chains.
  • Level conversion welds skin joint vertices to the skin and hair segment roots to the head (ProcessSkinJoints, ProcessHair); UpdatePlayerSkinVertices re-uploads the moveable vertices when the skin changes.

4.9 Level conversion

PrepareDataForTheRenderer (Scene/RendererCompatibility.cpp) converts the level and hands a Backend::LevelGeometry (pointers to the frontend vectors, which must outlive the level) to SceneRenderer::LoadLevel:

  • Rooms: vertices in world space; quads split into two triangles. Every bucket goes through GetPolygonChunks: buckets above 1024 polygons are split by median splits along the longest axis of their polygon centers, and each chunk becomes its own RendererBucket with world space bounds, so the backend culls it separately. Buckets are sorted by blend mode and texture. Room bounds exclude the outer wall sectors.
  • Room lights: sun, point, spot, shadow and fog bulb; shadow lights never cast shadows.
  • Moveables and statics: meshes, bone hierarchy and bind pose; skin joints and hair processing.
  • Animated texture sets (frames, UV rotate, video) and sprites (UVs and size).

The level vertex Structures::Vertex is 52 bytes; the backend repacks it into 40 byte room vertices and 48 byte object vertices (6.2).

5. Transparent sorting

Faces with blend modes that do not commute cannot rely on the depth buffer, so they are drawn back to front at the end of the scene pass. IsSortedBlendMode accepts every mode except opaque, alpha test, additive, distortion and fast alpha blend; objects faded below ALPHA_BLEND_THRESHOLD (1 - epsilon) turn opaque, alpha test and fast alpha blend buckets into alpha blend and join the list too. Sprites join with every mode except opaque, alpha test, additive and distortion (fast alpha blend sprites included). The frontend collects and sorts on the CPU; the backend turns the order into draw runs.

Data layout and collection

Every collection site fills one RendererSortableObject per bucket and calls CollectSortedBucket(view, object, world, cameraPosition). Each polygon center is transformed by the world matrix (rooms pass none: their vertices are in world space) and its distance to the camera stored. The object keeps its depth range and a normalized screen rectangle, projected from the eight corners of the bucket bounds computed at load (from polygon centers only for buckets without bounds); points behind the camera cover the whole screen. Per-instance products (bone times world, swarm interpolation) are computed once per mesh, not per polygon.

Groups

A group is the unit that draws as one batch. Its key (GetSortedGroupKey) is resolved only when the object index changes, since the polygons of an object are contiguous:

Moveable, hairItem + bucket + type

Clusters

Group order alone is wrong when two transparent objects overlap both in depth and on screen; only those are interleaved:

  1. BuildSortedClusters joins groups whose depth ranges and screen rectangles overlap with a union-find (path halving), sweeping candidates by near depth. Rooms and sprites never join a cluster.
  2. RankSortedClusters: rooms first, back to front by portal traversal; then objects back to front by mean distance quantized to GROUP_DEPTH_STEP (128); ties by blend priority (exclude, subtractive, lighten, screen, alpha blend, others; issue #1793), then by index.
  3. Inside a cluster polygons are in exact far to near order, so batches break wherever the group changes.
  4. SplitBusyClusters dissolves clusters with more than MAX_CLUSTER_GROUP_SWITCHES (64) group switches and sorts again, so a pathological overlap cannot become one draw per polygon.

Sort key

RadixSortKeys is a stable LSD radix sort on 8 bit digits. It builds all eight histograms in one pass and skips digits equal for all keys, so a typical scene needs three passes. The scratch buffer persists across frames.

Runs and draws

SceneRenderer::CollectSortedFaces walks the sorted keys and emits one run per sequence of polygons with the same group. Mesh runs copy their indices (6 per quad, 3 per triangle) from the CPU copy of the level index buffer into Frame.SortedIndices, uploaded once per frame, so a run is one indexed draw; water covered room buckets are skipped. Sprite runs append their sprites to the frame sprite buffer. GetSortedObjectInstance adds one instance per object (world, color, lights, bones) and reuses it when clusters split the object into several runs; hair reuses the hair instances; swarms force the alpha test. Room runs use instance 0; consecutive room runs that are contiguous and share draw state and scissor are merged (CanMergeSortedRoomRuns).

DrawSortedFaces changes pipeline, vertex streams and bindings only when they differ from the previous run, clips room runs to their portal rectangle and always uses pixel variant 0 (all maps, alpha test). Decals are not applied to sorted faces. Mirrors record their own list (CollectMirroredSorted) with the mirrored object pipeline.

Background

The design replaced a version that made every transparent polygon a 136 byte object sorted with std::sort. Seven alpha blended vases (about 12,600 triangles) took a debug frame from 4 to 16 ms; RenderDoc put the whole GPU frame at 7.2 ms, so the cost was on the CPU.

6. Backend

6.1 Initialization

SceneRenderer::Initialize(window, backend, gameDirectory, preferLowPowerGpu):

  1. CreateDevice (section 14); the shader directory is <game>/Shaders/Bin.
  2. Present mode: mailbox with vertical sync where SDL GPU supports it, otherwise vsync; immediate without vertical sync.
  3. Upload ring of 4 MiB and the render target pool.
  4. CreatePipelines (also run by F9 hot reload): room, object, inventory and sky shaders, the classic sky grid, then the resources of each feature in order: sprites, ambient occlusion, post-process, shadows, glow, DOF, SMAA, upscale, sky reflections, atmosphere, overlay (font), debug primitives, clouds, god rays, dust storm, water, TAA, bloom. Then the 105 pixel shader variants, the instance index stream (65536 entries, entry N holds N, never re-uploaded), the anisotropic material sampler (16x, clamp, mip bias) and the default textures: white, flat normal (128, 128, 255), default ORSH (255, 255, 0, 255) and black, also as one-layer arrays.

Render targets are created lazily on the first frame by EnsureRenderTargets.

6.2 Level load

LoadLevel(geometry) waits for the GPU, frees the previous textures first (so the geometry gets the freed memory) and then:

  • Geometry (SceneRendererGeometry.cpp): one vertex buffer Level.Vertices with the room region (40 byte GpuRoomVertex) and, at a 256 byte aligned offset, the object region (48 byte GpuObjectVertex, statics then moveables); one 32 bit index buffer Level.Indices with statics, moveables and rooms sections. UVs are packed as 16 bit normalized values (out of range UVs are clamped and counted). The CPU index copies stay for the sorted faces. UpdateMoveableVertices re-uploads the moveable section for skin and hair changes.
  • Water surfaces (section 10).
  • Textures (section 8), then the encoded blobs are freed.
  • Animated textures: frames (four corner UVs) and sets (first frame, count, fps, type, UV rotate direction and speed) in two storage buffers, plus one-frame sets for waterfalls and video textures.
  • Pipelines (PrecompileLevelPipelines, 6.8), logged as "N pipelines created at load".

6.3 RenderFrame

  1. Wait for the oldest frame fence; the wait time feeds the automatic render scale.
  2. Render scale: automatic (UpdateDynamicResolution) when the environment value is 0 or less, else the given scale.
  3. CollectUnused of the pool, ApplyHdrMode, EnsureRenderTargets, cloud noise upload on first use.
  4. Projection rebuilt for the target aspect and jittered by TAA (PrepareTemporalFrame); EnsureTemporalTargets.
  5. Frame uniforms: vertex slot 0 (FrameVertexUniforms), pixel slot 0 prepared, fog bulbs to vertex slot 3, defaults pushed to every other declared slot (an unpushed slot can lose the device on Vulkan).
  6. CPU collection: materials, decals, objects (lights, clusters, statics, moveables, player, effect meshes, mirrors, debris, gun flashes), draw sorting, room draws, water surfaces, underwater fog, sprites, sky sprites, sorted faces, mirrored sorted faces, debug primitives.
  7. UploadFrameData: one copy pass.
  8. Pass flags: shadows, distortion, sky reflections, DOF (and EnsureDOFTargets), bloom.
  9. The fourteen passes, each in a debug group with CPU time and draw count.
  10. Statistics, FinishTemporalFrame, submit.

6.5 Render targets

  • Render size = window size x render scale (clamped to 0.25..1; the automatic scale stays within 0.5..1). Frame targets have the window size and the swapchain format.
  • EnsureRenderTargets recreates what changed (window size, render size or scene color format), clears the pool and reserves the transient targets again (SMAA, scene and post-process copies, DOF, AO, glow, bloom steps with HDR), so they are allocated before the level fills the video memory; on Vulkan late allocations can land in system memory.
  • Targets that a pass may sample before writing are cleared once at creation, which keeps Vulkan image layouts defined.
  • Scene.Depth is a depth target only and never sampled (avoids depth decompression on Intel); passes sample the R32F depth copy.
  • Feature targets (velocity, TAA histories, DOF layers) exist only while the feature is active and are released when the render size changes.
  • The pool (RHI::RenderTargetPool) matches requests by description and destroys entries unused for 300 frames.
  • Material sampler mip bias = log2(render width / window width) below native scale (-0.585 at 67%), so textures keep the detail of the window resolution.

6.7 Objects, instancing and draw order

  • Lights: the view dynamic lights are written first (slice 0) and clustered.
  • Statics: one instance each, one instanced draw per bucket over the instance range of the object. Faded statics are drawn only as sorted faces.
  • Moveables: rigid meshes of items that are not skinned, fading, waterfalls or shadow casters are queued and flushed sorted by mesh, so identical items share one instanced draw per bucket. Full skins use bind pose times animation bones. Shadow casters copy their draws into the shadow draw list with a bounding sphere. Fading items move their opaque buckets to the sorted list.
  • Player: one classic skinning instance serves rigid meshes, joints and holsters; optional full skin; one instance per hair unit.
  • Effect meshes: room effects, gun shells, swarms (rats, bats, beetles, locusts, fish) and particle group meshes, all queued by mesh. Swarms share one light slice per room and frame.
  • Mirrors (section 10) reflect the draws collected so far; debris and gun flashes come after and are not reflected.
  • Room draws (CollectRoomDraws): per visible room and bucket, skipping water covered buckets, buckets outside the frustum (bounds +-128 for vertex effects) and buckets outside the portal rectangle. One draw per bucket; the portal scissor and room state are set when the room changes.
  • State sort (DrawSort): key = alpha tested (bit 60), texture array group (12 bits at 44), layer (12 bits at 32), material (16 bits at 16), mesh source; stable LSD radix sort that skips constant digits. Opaque, additive and distortion lists use it; the prepass keeps portal order (front to back, good for early depth) and alpha edges keep collection order.
  • BindBucket skips pushes and binds equal to the previous state; pages of one texture group change only the layer uniform.

6.9 Scene pass

The scene pass loads the color written by the sky pass and the prepass depth. Water surfaces and the underwater fog need copies of the scene, so they end the render pass and reopen it. Blend modes other than opaque, alpha test, additive and distortion reach the screen only through the sorted faces.

7. Lighting and materials

Shaders: Rooms.hlsl, Objects.hlsl, Lighting.hlsli, LightClusters.hlsli, Materials.hlsli, Shadows.hlsli, Decals.hlsli, FogBulbs.hlsli, Skinning.hlsli, Common.hlsli. Colors use COLOR_MODULATION_SCALE = 2 (a neutral vertex color is 0.5).

7.1 Light model

  • Sprites are lit once per sprite on the CPU (GetSpriteLight) from the view dynamic lights at the sprite center, for opaque, alpha test and alpha blended default sprites: far cheaper than per-pixel lighting of overdrawn particles.
  • Loops over lights are bounded by LIGHTS_PER_DRAW_MAX (256) so a corrupted count cannot hang the GPU.

7.2 Light clusters

  • Grid: LIGHT_CLUSTER_TILES_X 16, TILES_Y 9, SLICES 24; up to LIGHT_CLUSTER_LIGHTS_MAX 64 dynamic lights per view.
  • Slices are logarithmic between 256 and 65536 world units: slice = floor(log2(max(w / 256, 1)) * 3), three per doubling.
  • The CPU (BuildLightClusters) projects, for each slice a light sphere covers, the view space box of the sphere cut to the slice depths and marks the covered tiles.
  • Room and object pixels find their cluster from the jittered view-projection and walk the set bits with firstbitlow; positions outside the screen fall back to the full loop.
  • With more than 64 dynamic lights the masks stay empty and the shaders loop over every light (bounded at 256). With an orthographic projection every cluster holds every light.

7.3 Shadows

  • Shadow map (SceneRendererShadows.cpp): one point or spot light, the shadow light picked by the frontend. A cube of six R32F layers (Shadow.CubeMap, a 2D array, since SDL GPU has no depth arrays) plus a shared D32F depth; size from the configuration (default 1024, minimum 64). FOV 90 degrees, near 16, far = the light outer radius.
  • Casters: moveables with a shadow type (only the player with the player shadow mode); rooms and statics do not cast. Draws are culled per face with their bounding sphere.
  • Receivers: rooms always; objects only when shadowable (moveables with a shadow type); statics never. Opaque, alpha test and alpha blend surfaces only.
  • Sampling (DoShadow): the position is projected into the face that contains it and filtered with a 5 x 5 PCF (25 point taps) without depth bias. The darkening is 1 - (1 - shadow) * 0.6 * lightFactor, where the light factor is the shadow light falloff times its intensity, independent of its color, with a facing fade (bias -2.5 for rooms, -0.5 for objects).
  • Blob shadows: up to 16 spheres; each darkens linearly toward its center, spheres combine multiplicatively, at most 30% darkening. Used when shadow maps are off and alongside them.

7.4 Materials

Each texture page has up to four maps: color, normal (tangent space, Z rebuilt), ORSH (R ambient occlusion, G roughness, B specular, A height) and emissive. GpuMaterial holds a type (default, reflective, sky reflective), flags (height map, AO map, emissive map) and four property vectors.

  • Parallax occlusion mapping: materials with a height map and an ORSH map; 1 to 16 steps (fewer at steep angles), height scale 0.0035, faded out between 5000 and 7000 units.
  • Ambient occlusion: pow(GTAO, 1.5) times the ORSH occlusion, for opaque, alpha test and alpha blended surfaces (alpha blended surfaces fade it by alpha).
  • Reflective materials sample the half resolution copy of the previous frame along the reflected view vector (not a ray traced reflection); sky reflective materials sample the dual paraboloid sky map. Tint, strength and a vertical mask come from the material properties.
  • Emissive is added to the lighting, written to the prepass emissive target and blurred into the glow.
  • Animated textures: frame sets (fps based), UV rotation (scroll per vertex, wrapped per pixel), video sets (the current video frame) and legacy waterfalls (objects, one-frame sets scrolled at speed 10).

7.5 Fog, fog bulbs, decals and caustics

  • Distance fog: per vertex, linear between the level fog start and end (in sectors). Blend modes that add light fade toward fog times luma; subtractive and exclude toward fog times inverse luma; alpha blend fades the fog alpha with the color alpha. Sprites fog toward black.
  • Fog bulbs: per vertex, up to 32: density = length of the camera ray inside the sphere x density. Rooms and objects subtract the bulb density and add its color; sprites dim by its luma; only the first classic sky layer uses them.
  • Decals: rooms only (not animated buckets, sorted faces or the prepass), up to 64 per draw, when the decals option is on: noise perturbed discs in the tangent plane that darken the lighting.
  • Caustics: rooms flagged water without the no-caustics flag, when the caustics option is on. The caustic sprite sequence is animated per frame and projected from above (2048 unit tiles), weighted by upward facing normals.

7.6 Vertex effects and skinning

  • Wibble (glow and move bits): a sine with a 64 frame period, phased by the position hash; move displaces weighted vertices vertically up to 128 units; glow modulates the brightness.
  • Water refraction wobble: when the camera and a room are on different sides of the water, room vertices wobble in clip space. Disabled in levels with generated water surfaces (section 10).
  • Skinning (Skinning.hlsli): none (0), rigid (1, first bone), full (2, four weighted matrices), classic (3, quaternion blend with hemisphere flip and the translation of the first bone).

8. Textures

  • Sources: Tomb Editor writes each map as an encoded blob in the .ten file. With texture compression on (level option) maps are DDS with the full mip chain: BC1 for opaque or 1 bit alpha maps, BC3 otherwise, BC5 for normal maps; they are uploaded as they are. With compression off maps are PNG, decoded to RGBA8 with mips generated on the GPU (four to eight times the memory; the log counts these maps). The engine does not compress or convert textures at load.
  • Accepted DDS: legacy FourCC (DXT1, DXT3, DXT5, ATI1/BC4U, ATI2/BC5U, uncompressed 32 bit) and DX10 headers with UNORM RGBA8, BGRA8, BC1 to BC5 and BC7. sRGB variants are not accepted; the data must hold every declared mip, largest first.
  • Groups (LoadTextureArrays): a page joins the first group whose four maps match it in width, height, mip count, format and generated-mip flag; each present map of a group becomes a Texture2DArray (LevelPages[g].Color and so on). Layers are decoded in parallel in chunks of 8 pages. Animated texture pages and the sky page are color only.
  • Missing maps bind one-layer default arrays and select a shader variant that does not read them.
  • Budget (FitArrayGroupsToBudget): on GPUs with at least 1 GiB of dedicated memory, if the arrays do not fit min(process budget, dedicated memory - memory of other processes) minus a reserve of max(512 MiB, 10%), one then two top mips are skipped, emissive first, then ORSH, normal and color. Generated-mip maps and integrated GPUs keep every mip.
  • Other textures: sprite atlases stay single textures (the 2D layer samples them too); the font is a DirectXTK .spritefont parsed by Font; menu images, loading screens and the logo are PNG (SDL), JPEG (stb_image) or DDS decoded by TextureLoader; video frames are uploaded as BGRA8 each frame; noise (clouds, water waves) is generated, SMAA lookup textures are embedded.

9. Sky and atmosphere

The frontend (Renderer/Sky/, Renderer::PrepareSkyEffects) advances the state of each effect and fills uniform blocks and draw records (Backend/SkyTypes.h: CloudLayerDraw, SkyEffectFlags, GodRayDraw, HorizonLayerDraw, DustStormDraw). The dome, clouds and horizons are prepared only when a visible room has the skybox flag; god rays and the dust storm always. The weather presets and transitions live in Game/Sky/SkyCloudSystem.*. The backend replays the records in the sky pass.

Atmospheric dome, sun, moon and aurora

  • Dome (AtmosphericSky.hlsl, SceneRendererAtmosphere.cpp): a fullscreen triangle at the far plane, depth tested against the prepass, so texels covered by geometry are not shaded. An artistic zenith density and absorption model with Rayleigh and Mie terms, sun glow, warm tint by sun elevation and horizon darkening, then exposure, Reinhard tonemapping and gamma 2.2; a night gradient with moon glow blends in by sun elevation. Below the horizon it fades to the level horizon color.
  • Sun direction comes from the global lens flare pitch and yaw, its color from the lens flare color.
  • Sun and moon discs are drawn after the clouds, masked by the cloud coverage stored in the scene alpha; the moon has a procedural surface and a phase from the sun direction.
  • Aurora: a raymarch of horizontal layers (25 to 75 steps) with triangle noise, color presets and a fade in; at Low quality half resolution and fewer octaves.
  • Underwater sky: caustics and a Snell window over a projected plane, enabled by the water surface preset.

Volumetric clouds

  • Two layers (A and B) from the weather presets; noise generated once on the CPU: a 128^3 RGBA8 3D texture (Perlin, value noise, curl) and a 256^2 RG8 Worley texture.
  • Each layer is raymarched into its own RGBA16F target at a quarter of the window size with a history target: a flat slab above the camera (default 1536 units above it, 2500 thick), adaptive step counts, 5 octave FBM with curl warp and distance LOD, an artistic lighting model (height gradient, silver lining, forward scatter, sunset underside, moon light) and lightning.
  • Temporal reprojection: checkerboard rendering, the other half from the reprojected history with an alpha band test; disabled on fast motion.
  • A bilateral upsample composites each layer into the scene with a hybrid screen and alpha blend; the scene alpha accumulates the coverage that discs, aurora, stars and god rays read.
  • The "bleed" overlay replays the alto layers after the horizon meshes so clouds pass in front of them.
  • Clouds are not depth tested: every texel of the quarter resolution target is marched.
  • Lens flare occlusion: every 3 frames the cloud transmittance toward the sun is marched into a 1 x 1 R32F target and read back asynchronously; the frontend smooths it (0.6) and scales the global lens flare and the sun sprite by it.

Classic sky, stars and horizons

  • Two classic additive layers on a 20 x 20 tile grid (10240 units) at camera height - 1536, scrolled by the weather, skipped when their color is black; drawn depth tested at the far plane.
  • Stars and meteors are sprites (PSSky) hidden inside the moon disc and under the cloud coverage of the previous frame.
  • The classic sun sprite appears only when the dome is off. Up to two horizon meshes follow the camera with alpha and gradients.

God rays and dust storm

  • God rays: a horizon silhouette and a radial march toward the sun (or the moon at night) at half resolution, with sources from cloud gaps and a virtual sun disc, composited additively. Samples are capped by the sky quality; the underwater sky turns them into light shafts.
  • Dust storm: marched at the end of the scene pass up to the prepass depth (up to 12 geometric steps of triangle noise advected by the wind), alpha blended; indoors limited to the outdoor mask (the normal target alpha) and up to four portal bleed volumes.

Sky reflections

A dual paraboloid map (SkyReflections, two 512 x 512 RGBA8 layers) rendered every frame while a sky reflective material exists or water reflects a visible sky. It contains the classic layers and horizon meshes only: no dome, clouds, stars or aurora.

10. Water surfaces, underwater fog and mirrors

Water surfaces

Classic levels have no water surface geometry: surfaces are the horizontal portals between a water room and a dry room above it. SceneRendererWater.cpp builds them at load. This computation is temporary: it will move to Tomb Editor, which will write the surfaces into the level.

  • A portal qualifies when it is flat (corners within 1 unit) and the dry room is above. Each becomes a flat grid of 256 unit cells (at most 128 per side) with a swell weight per vertex that fades over 512 units toward edges not continued by another surface.
  • Builder-made faces that fake a surface there (non-opaque buckets flat at the surface height) are hidden in room and sorted draws; the count is logged.
  • Wave normals: a 256 x 256 RGBA8 map (9 mips) summing 32 random sine waves.
  • Drawing, in the scene pass after the opaque and alpha edge draws: copy the scene, trace reflections at half resolution (10 screen space steps with binary refinement, skipped where Fresnel is low), then draw each surface with four Gerstner-like swells in the vertex shader, three scrolling normal layers, refraction (fallback where the offset hits geometry in front), Beer-Lambert absorption, Fresnel (IOR 1.33 from below with total internal reflection), an environment fallback (sky texel, sky reflection map, room ambient) and specular from the clustered room lights. Water does not write depth.
  • With generated surfaces the classic room refraction wobble is turned off.
  • Water parameters (color, absorption, flow, wave strength) are constants for now.

Underwater fog

Whenever the camera room is a water room, a fullscreen pass after the water surfaces absorbs light along the view ray (density 0.35), shortened for rays leaving through the surface height. It runs in levels without generated surfaces too.

Mirrors

  • Mirrors come from the level (room, plane, flags ReflectPlayer, ReflectMoveables, ReflectStatics, ReflectSprites, ReflectLights); there is no Lua API. A mirror is active only while the camera or the player is in its room.
  • The backend (SceneRendererMirrors.cpp) has no pass of its own: it copies the player, moveable and static instances of the mirror room allowed by the flags, multiplied by the reflection matrix, and draws them right after their normal counterpart with front face culling. Their lights are copied (reflected with ReflectLights) and the view dynamic lights appended, since the clusters are placed for the unreflected view.
  • With ReflectSprites all unsorted sprites of the frame are reflected; all non-room sorted faces and sprites are reflected regardless of the room; sorted room faces never.
  • Room geometry is never mirrored (the reflected room must be built in the level) and nothing clips the copies to the mirror plane.

11. Sprites, debris and gun flashes

  • Sprites (SceneRendererSprites.cpp, Sprites.hlsl): corners expanded on the CPU (billboards, constrained, look-at, 3D quads), drawn instanced as 6 vertices per sprite from Frame.Sprites. Unsorted runs merge by texture, blend mode, soft flag and render type. Opaque and alpha test sprites write depth and draw with the opaque group; additive sprites with the additive group; the rest through the sorted faces.
  • Soft particles fade where the particle approaches the depth copy (alpha = min(alpha, (scene - particle) * 1024)) and are discarded behind it.
  • Laser barriers and beams have their own pixel effects (SpriteEffects.hlsli).
  • Debris (SceneRendererDebris.cpp): one instance per fragment (interpolated transform, room ambient, no lights), three vertices per fragment, merged by page and blend mode, no culling; opaque in the opaque group, additive in the additive group, other modes after the sorted faces, unsorted.
  • Gun flashes (SceneRendererEffects.cpp): player weapons and creature muzzle flashes, collected in the backend from the interpolated bones and drawn additively after the sorted faces.

12. Post-processing

Fullscreen passes use RenderFullscreenPass (one color target, a fullscreen triangle from Fullscreen.hlsli, no depth) and push their uniforms to pixel slot 2.

12.1 GTAO

  • Occlusion (GTAO.hlsl, half resolution, pooled R16F): ground truth ambient occlusion with one slice per texel and frame and 4 horizon steps per side, radius 192 world units (at most 0.1 of the screen), normals reconstructed from the depth copy, interleaved gradient noise rotated over 16 frames.
  • Temporal accumulation (PSTemporal): a 3 x 3 bilateral filter (spatial sigma 3, depth sigma 0.3), then the history fetched through the motion vectors (TAA on) or the camera reprojection, clamped to the neighborhood +-0.1 and blended with weight 0.85 into GTAO.History (two half resolution R16F targets).
  • The scene samples the history bilinearly with exponent 1.5. The history resets on camera cuts, target creation and frames without AO.
  • AO needs the configuration option and the level setting Graphics.ambientOcclusion.

12.2 TAA and motion vectors

  • Jitter: 8 Halton(2, 3) sub-pixel offsets added to the projection; the unjittered matrices are kept for motion vectors and clusters use the jittered one.
  • Motion vectors: written by the prepass into an RG16F target only while TAA is active, in UV units. Objects use the previous world and bones of the same item (cached per item number, valid if drawn in the previous frame); rooms, statics, effects and debris move with the camera only; vertex effects are not part of the motion. Texels without geometry reproject with the camera matrices.
  • Resolve: TAA.hlsl, a compute shader with 16 x 16 groups (the first compute pass of the RHI): gathers an 18 x 18 tile into group shared memory, variance clipping in YCoCg (mean +- 1 deviation of the 3 x 3 neighborhood), motion of the nearest texel, Catmull-Rom history, luma weighted blend with current weight 0.1. The 8 bit history uses stochastic rounding so slow blends converge; the TAA_HDR permutation keeps a half float history.
  • The history resets on camera cuts (a jump of more than two sectors), when TAA turns on, and when the targets are created (render scale changes included).
  • Menu frames use SMAA instead, since they have no history.

12.3 Automatic render scale

The automatic scale holds the refresh rate (high framerate) or 30 fps between 50% and 100%. It measures the frame interval and the time the game thread waits for its frame fence: a long wait means the GPU is the bottleneck. Each change recreates the scene targets and is logged. Below native scale FSR 1 upscales the result.

12.4 Depth of field

  • Modes (View.SetDOF): none, full, front, back; active when the strength is above 0. The far layer exists unless the mode is front, the near layer unless it is back.
  • Half resolution RGBA8 targets created on first use. Steps: downsample with a signed circle of confusion clamp((z - focus) / range, -1, 1) raised to 1.3 in alpha; far blur (12 tap disc, radius up to 8 texels, depth aware weights); near CoC dilation (8 taps); near blur.
  • The post-process blends the far layer, then the near layer, by their CoC.
  • The menu background blur uses the same passes.

12.5 Glow and reflection copy

  • Glow: the prepass emissive is downscaled to a quarter (9 taps) and blurred with a separable Gaussian (sigma 10, radius 24, 12 bilinear taps per side). The post-process adds it with a soft add 1 - (1 - c)(1 - g) in 8 bit and a plain add with HDR. It runs only when an emissive material is visible.
  • Reflection copy: the resolved scene downscaled to half resolution, read by reflective materials in the next frame.

12.6 HDR and bloom

  • Off (default): the scene target has the 8 bit swapchain format and the scene shaders clamp colors to 1 (SceneColorMax = 1).
  • On (SceneRendererBloom.cpp): the scene target is RGBA16F and the same shaders clamp to 64, so the 8 bit mode keeps identical results. The TAA history is half float. The post-process adds the bloom, multiplies by the exposure and tonemaps with the identity up to 0.8 and an exponential shoulder above, so colors of the 8 bit range keep their look.
  • Bloom: five pooled steps from half resolution down, R11G11B10F where supported (RGBA16F otherwise). The first step keeps the colors above the threshold with a soft knee (half the threshold) after a 13 tap downsample and compresses them by luma; each next step halves the previous one; then each step is upsampled with a 3 x 3 tent filter and added onto the next larger one. The post-process adds the half resolution step times BloomIntensity / 5.
  • Switching: ApplyHdrMode waits for the GPU, recreates the pipelines registered with CreateSceneColorPipeline (sky, aurora, clouds, god rays, dust storm, water, underwater fog, debug primitives) and empties the scene pipeline caches; the scene targets are created in the new format by EnsureRenderTargets.
  • HDR needs RGBA16F as color target, sampler and compute storage (for the TAA history); otherwise the device stays in 8 bit mode.
  • The distortion target, the DOF layers and the reflection copy stay 8 bit; there is no HDR10 swapchain output.

12.7 Post-process pass

  • Distortion: the half resolution payload stores strength weighted emitter depth and type; the shader offsets the scene lookup with simplex noise and shimmer (different for surfaces and billboards), scaled by perspective, faded with distance (4096 to 10240), rejected where the refracted texel is in front of the emitter.
  • Lens flares: up to 8, projected on the CPU; visibility from 9 depth taps around the flare (sky texels only); starburst, glows, ghosts and anamorphic glare.
  • Color schemes (PostProcessMode): monochrome, negative, exclusion, blended by strength.
  • Tint and gamma: saturate(pow(saturate(c * Tint * 2), 1 / Gamma)), neutral tint 0.5.
  • Output: Frame.Color at native scale, the pooled upscale source below it, or a pooled source that SMAA resolves when SMAA is set.

12.8 SMAA

SMAA 1x, ultra preset (threshold 0.05, 32 search steps, 16 diagonal steps, corner rounding 25), color edge detection. Three passes: edges (RG8), blending weights (RGBA8, with the area and search lookup textures) and neighborhood blending. Where a stencil format is supported, the edge pass marks edge pixels and the weight pass runs only on them. Menu frames use SMAA for their antialiasing too.

12.9 FSR 1

  • The Upscale pass runs AMD FSR 1 EASU (FSR.hlsl, half precision paths, FidelityFX code in Shaders/FidelityFX) from the upscale source to the window size Frame.Color.
  • RCAS is not a pass: the 2D layer draws the scene background quad with the Overlay.RCAS pipeline after EASU, and with TAA at native scale. Its sharpness is 0.2 stops below the maximum (RCAS_SHARPNESS); the half precision path reads it as a pair of halves.
  • With TAA below native scale the TAA resolve runs at the render resolution and FSR 1 upscales its result. A temporal upscaler inside the TAA resolve was measured and removed (section 19).

13. 2D layer, video and ImGui

  • UiFrame (Backend/OverlayTypes.h): texts, bars, sprites (800 x 600 display space), images (normalized coordinates) and 3D objects, in layers that keep the order of the frontend calls, plus background fade, gamma, menu flag, antialiasing mode, flash color, binocular or laser sight overlay and the ImGui draw data.
  • FinishFrame (SceneRendererOverlay.cpp): waits for a frame fence only if no scene was rendered, loads overlay images (decoded without mips), uploads the overlay and ImGui vertices, draws the scene background quad (times the background fade; RCAS when sharpened), then the layers with merged runs: glyphs of the SpriteFont, 9 slice bars with a fill and poison pulse, sprites, images (the path <video> maps to the video texture), screen overlays, 3D objects.
  • 3D menu objects (inventory, pickups, compass, title objects): each object range is a render pass with its own view-projection and depth, using the inventory shaders (a fixed sun, sun specular, emissive, gamma) and writing emissive to a second target. Menu frames then run their own glow and SMAA (RenderMenuPostProcess).
  • Video (SceneRendererVideo.cpp): each BGRA8 frame is uploaded to a 2D texture and a one-layer array; animated buckets with a video set and video sprites show it.
  • ImGui (SceneRendererImGui.cpp): the font atlas is recreated when its generation changes; one draw per command with a scissor. ImGui has no backend of its own: the scene renderer draws its draw data.
  • The final target is blitted to the swapchain on the game thread (DirectX 11, OpenGL) or the window thread (SDL GPU).

16. Shaders

  • Each .hlsl declares its entry points in header lines: 
    // TEN_SHADER: <Vertex|Pixel|Compute> <Entry> samplers=N storage_textures=N storage_buffers=N uniform_buffers=N
//     [rw_storage_textures=N rw_storage_buffers=N threads=X,Y,Z permutations=A,B options=A,B hlsl=YEAR]
    permutations= adds one variant per define (for example TAA.CS.TAA_HDR); options= adds a variant for every combination (the map variants of rooms and objects, named like NO_ALPHA_TEST.NO_ORSH_MAP).
  • CompileShaders.ps1 runs as a pre-build step and writes Build/<Config>/Shaders/Bin: DXBC with FXC (*_5_0), SPIR-V with the DXC of the Vulkan SDK (*_6_0, Vulkan 1.0, DX layout), DXIL with the DXC of the Windows SDK (signed by its dxil.dll), GLSL 450 with SPIRV-Cross from a patched copy of the SPIR-V. A missing compiler disables only its backend; FXC or the Vulkan DXC is required. Builds are incremental (sources, includes and the script); Debug builds add debug info.
  • GpuShared.hlsli declares the structures shared with C++ (included by Backend/GpuTypes.h), so layouts are written once; ShaderInterop.hlsli maps uniform blocks, storage buffers and texture sampler pairs (TEN_PS_UNIFORMS, TEN_PS_TEXTURE and similar) to each API.
  • Graphics shaders are Shader Model 5.0 compatible; FSR uses the HLSL 2018 language version.
  • Hot reload: in a Debug build started with debug, F9 runs CompileShaders.ps1 from the repository on the shader directory, then recreates the pipelines; on failure the previous shaders stay.

21. Roadmap

Goals

  1. 30 fps on giant levels with integrated GPUs and discrete GPUs from 2015 on, low settings, 1080p.
  2. Less video memory with many materials (some levels reach 5 GB today).
  3. Vulkan at full speed with the features of 2016+ GPUs, through SDL GPU (kept for portability, including Metal); older GPUs use DirectX 11 with lower settings.
  4. Modern asset handling (GPU-ready meshes, single textures instead of atlases), LOD and mip mapping in the format and the renderer.

Hardware tiers: modern (GCN, Pascal, Intel Gen9 and newer; Vulkan 1.2 through SDL GPU with multi draw indirect, draw parameters and subgroup operations requested through SDL_GPUVulkanOptions) gets GPU culling and sorting; compatible (older GPUs, DirectX 11) keeps the CPU paths with the same data. Excluded: mesh shaders, ray tracing, bindless and GPU draw counts (not exposed by SDL GPU).

S items concern the sorted faces, R items the rest of the renderer. Already done: motion vectors and TAA, automatic render scale, clustered lights for objects and sprites, temporal GTAO, optional HDR, block compressed textures from Tomb Editor, feature targets only while active.

  2. Cheap items that keep the look: S1, S2, S8, R11.
  3. Transparent pass and particles: S3, S5, S4.
